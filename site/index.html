Approve from wherever you are

“I want my agent to keep working when I step away, but it stalls on the first approval prompt.”

Most of what an agent does is safe. The trouble is the few calls that aren't, and a prompt on a laptop you just walked away from.

  • The request comes to your phone. Approve or deny with a tap in Telegram, or open the approval page and confirm with your passkey.
  • Safe calls never wait. Rules per tool and per argument decide what's allowed, what asks you and what's denied. Reading an issue goes through; posting a comment asks.
  • Answer once, not every time. “Allow always” and “Deny always” remember a decision for the exact call or the tool, within limits the gateway checks.

    An installable approval app with push notifications. The notification says what's being asked, with Approve and Deny right on it, and the app keeps your approval history.

See what you're approving

“Honestly, I click yes without really reading what it's asking.”

A tool name and a blob of JSON don't tell you much. So people stop reading, and an approval prompt turns into a habit.

  • Previews of the real thing. The file change as a diff, the email as it will be sent, the full text of a comment and the issue it goes on.
  • Built by the gateway, not the agent. Previews come from the checked arguments and read-only lookups the gateway makes itself, so the agent can't dress up what you see.
  • The agent's own words are fenced off. An agent can explain why it wants something. That text is shown separately and labelled as written by the agent.
  • No preview, no pretending. If a preview can't be built, the page says so and shows the raw arguments. It never approves on its own.

Rules the agent can't get around

“I set up careful auto-approve rules. The agent still found a way around them.”

Rules inside the agent are suggestions to a program that can rewrite its own setup, call a different tool or simply log itself in somewhere else.

  • The agent never holds the credential. Tokens for GitHub, Google and Home Assistant stay with the gateway, under a different user. The agent only gets a gateway token.
  • A floor no agent can lower. Deny and ask rules in the policy floor beat every agent file, shared rule set and remembered “Allow always”.
  • It can't hand itself more access. Adding collaborators, creating deploy keys, setting Actions secrets and changing branch protection are denied in the shipped GitHub rules.

One agent, blocked on GitHub, tried to log itself in to GitHub with full repo access. Behind AgentPass there's no token on the agent's side to find, and the things that would give it lasting access are denied by default.

Nothing on the agent's side to leak

“My agent did something serious I never meant it to, and a secret got out.”

When the agent holds the keys, one bad instruction or prompt injection can use them in ways you never intended.

  • No secrets to exfiltrate. The agent can read everything it has and still not find a service token.
  • Risky actions need a person. Sending mail or changing a file asks you first, the most sensitive calls can require your passkey, and deleting a repository is denied outright.
  • Every call is on the record. The audit log keeps who asked, what was called, what was decided and by whom, and the agent can't edit it.

Example: GitHub with you in the loop

Your agent triages issues and drafts replies. Nothing reaches GitHub until you've seen it.

  1. The agent drafts a reply to an issue and asks AgentPass to post it.

  2. Your phone shows the full comment and the issue it goes on, in the right repo.

  3. You read it, then approve or deny.

  4. The gateway posts it with its own token. The call is in the audit log.

How it works

AgentPass sits between your agent and the services it uses. The agent asks; the gateway decides, asks you when needed, and makes the call.

  • The agent connects over a local Unix socket, a WebSocket, or MCP, with its own token. Each agent gets its own rules and its own audit trail.
  • The gateway decides. Deny beats allow, allow beats ask. When a call needs you, it builds the preview and sends the request to every approval channel you've set up.
  • The first valid answer wins. Then the gateway makes the call with its own credentials and returns only the result to the agent.
